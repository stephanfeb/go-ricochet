# Backlog

The open findings from the [2026-09-13 release audit](audit-2026-09-13/README.md)
that sat below its blocker line, plus anything found since. The eleven
blockers are done (see the status note at the top of the audit). This file
is the working list: one item at a time, one commit per item, the full
suite on a fresh database after each, the row updated in the same commit.

**How to use this file.** Pick the next `open` item, verify its anchors
(line numbers drift), fix it, add the test that would have caught it, mark
the row `done <commit>`. When an item is deliberately not going to be
fixed, mark it `wontfix` with one line of reasoning so it is not
re-investigated. Anchors are `file:line` as of the commit that last edited
this file.

Suggested order: the four correctness bugs a user can hit today (P5, P4,
P3, S1), then the one security item with no workaround (S2), then the rest
by section.

## Security

| ID | Status | Item |
|----|--------|------|
| S1 | open | **Patch If-Match is checked outside the transaction.** `internal/storage/postgres/postgres.go:685` `PatchDocument` reads with `GetDocument`, compares `ContentHash` to `ifMatch`, then calls `PutDocument(..., ifMatch=nil)`, so two concurrent patches both pass the check and the second overwrites the first. Fix: pass `ifMatch` through to `PutDocument` (it already does the compare-and-swap inside its transaction) or do read-merge-write in one tx with `SELECT ... FOR UPDATE`. Test: two goroutines patch the same doc with the same If-Match; exactly one must get 409. Audit A M-1, B H6. |
| S2 | open | **Registry and presence trust the JSON `server_id`, not the GossipSub signer.** `internal/registry/registry.go:218-236` uses `msg.ReceivedFrom` only to skip its own messages, then stores the announcement under `info.ServerID` from the payload. Presence events (`internal/presence/events.go:34,59,73`) are decoded the same way. Any peer on the topic can overwrite another server's entry or publish presence for peers it does not have. Fix: key entries by `msg.GetFrom()` (the signed publisher) and refuse a payload whose `server_id` differs; same for presence. Test: publish an announcement with a forged `server_id` from a second host; the registry must keep the real entry. Audit A M-3. |
| S3 | open | **Raw Postgres error text reaches clients.** `internal/protocol/mma/handler.go:234,266,292,327,390,443` and `internal/protocol/msa/handler.go:182,280` put `err.Error()` in the response; SCA does the same. A constraint name or SQL fragment is an information leak and a wire contract nobody meant to make. Fix: classify with `wire.Classify` and send a fixed message per status; log the real error server-side with the request id. Test: force a storage error and assert the response carries no `pgx`/`SQLSTATE`/table name. Audit A M-6. |
| S4 | open | **Directory search is an unbounded, unescaped `ILIKE`.** `internal/storage/postgres/postgres.go:919` builds `coalesce(display_name,'') ILIKE $n OR coalesce(bio,'') ILIKE $n` with `%q%`; `%` and `_` in the query are wildcards, there is no length cap, and the FTS index is unused. Fix: cap query length, escape `%`/`_`, use the `tsvector` index (`schema.sql` has it) with `plainto_tsquery`, keep `ILIKE` only as a prefix fallback. Check the handler does not log the full SQL at Info. Test: query `%` returns nothing rather than everything. Audit A M-6, B M3. |
| S5 | open | **Every per-peer limit is keyed by a free identity.** Rate limits, admission per-peer caps, mailbox quotas and forwarding trust are all per peer ID, which costs nothing to mint; nothing is IP-scoped. Design-level: decide whether an IP-scoped connection cap at the gater (`internal/trust`) is wanted. If not, mark `wontfix` and say so in README Security. Audit A M-7. |
| S6 | open | **Unbounded client strings persisted as index keys.** Folder path was bounded in B6 (`core.MaxFolderPathLength`). Still unbounded: document content type (`internal/protocol/sda/handler.go`), collection key and name (`sca`), feed title/description (`sfa`), directory display name and bio (`sda` directory ops). `validatePath` exists in each handler (`sfa:677`, `sda:1072`, `sca:715`) and is the place to add sibling validators. Fix: one bound per field (256 bytes is the folder-path precedent; bio maybe 4 KiB), rejected as 400. Test per field. Audit A M-8. |
| S7 | open | **World-readable stores are undocumented.** Documents, feeds, collections and the directory are readable by any peer by design; README never says so. Fix: a paragraph in README Security stating the visibility model per store, and in `doc/MAILBOX_LIFECYCLE_AND_ACLS.md` if it belongs there. Audit A I-1. |
| S8 | open | **Encryption has no forward secrecy and is not bound to the envelope.** `pkg/client/encryption.go` NaCl box with static X25519 keys derived from the identity; ciphertext is not bound to sender/recipient/folder, so a captured ciphertext can be replayed into another folder. Design-level. Minimum: include recipient, folder path and message id as associated data or in the plaintext header and verify on decrypt; document that forward secrecy is out of scope. Audit A L-3. |

## Performance

| ID | Status | Item |
|----|--------|------|
| P1 | open | **Submission is five round-trips plus a count plus a trigger.** `internal/storage/postgres/postgres.go:236` `StoreMessage`: tx begin, sequence `UPDATE ... RETURNING`, insert, then `trg_message_access` (`schema.sql:287-297`) updates the mailbox row again inside the same tx; the MDA adds a `COUNT(*)` for the cap and, for public mailboxes, two DELETEs with a sort per message. Fix: fold the count into the sequence update (`UPDATE mailboxes SET seq = seq+1, message_count = ...`), drop the trigger in favour of the same statement, move public-mailbox pruning to maintenance. Measure with `ricochet-bench` before and after (`doc/BASELINES.md`). Audit B H1. |
| P2 | open | **Three or four Info log lines per request on the hot path.** Counts today: msa 2, maa 4, mma 5, sda 3 (`grep -c Logger.Info internal/protocol/*/handler.go`). Fix: one Info line per request at the response writer (status, op, duration, peer), everything else Debug. Audit B H2. |
| P3 | open | **Notifier is built before the presence monitor, and never leaves a topic.** `internal/server/server.go:442` constructs `mda.NewNotifier(..., s.presenceMonitor, ...)` while `s.presenceMonitor` is assigned at `:455`, so the notifier's presence check (`internal/mda/notifier.go:110`) is always nil and it dials every recipient, online or not. `notifier.go:154` joins a GossipSub topic per shared/public mailbox and nothing leaves. B7 bounded the goroutines (`WithWorkers`). Fix: build the monitor first (or give the notifier a setter called after), and leave topics on mailbox delete or after idle. Test: with the monitor reporting a peer offline, no stream is opened. Audit B H3, C M2. |
| P4 | open | **Presence marks every still-connected peer offline after 120 s.** `internal/presence/service.go:103` writes `connectedPeers[pid] = time.Now()` at connect only; the sweep at `:331-336` evicts anything older than `TimeoutDuration`. A peer connected for two minutes is announced offline while its connection is up. Heartbeat (`:291-294`) serialises every online peer ID into one message and hits the 1 MiB pubsub cap around 18k peers. Fix: refresh the timestamp from the connection notifier (or check `host.Network().Connectedness` in the sweep); paginate or delta-encode the heartbeat. Test: a peer connected for longer than the timeout stays online. Audit B H4. |
| P5 | open | **`GetOrCreateMailbox` is check-then-insert.** `internal/storage/postgres/postgres.go:111`: a `SELECT` then an `INSERT`; two concurrent first deliveries to the same new mailbox race and the loser gets a unique violation, which surfaces to the sender as a failed submit. Fix: `INSERT ... ON CONFLICT (owner_peer_id, folder_path) DO UPDATE SET last_access_at = NOW() RETURNING *` in one statement. Test: N goroutines deliver to a fresh mailbox; all succeed, one row exists. Audit B H6. |
| P6 | open | **Shutdown drains nothing.** Handlers are registered with `host.SetStreamHandler` after `forge.Start` (`internal/server/server.go:489-499`), which forge's `Stop` does not track (`../go-p2p-forge/forge.go:32,134`), and `Server.Stop` (`server.go:161-182`) cancels the context and closes storage under in-flight queries. Fix: on stop, remove stream handlers, wait for in-flight requests (the admission controller knows the count) up to `ops.drain_delay`/`shutdown_timeout`, then close storage. Test: a request in flight during `Stop` completes or gets a clean 503, never a pool-closed error. Audit B M8, C M1. |
| P7 | open | **Heavy reads.** `GetDocumentHistory` (`postgres.go:777`) and HEAD load full bodies to report sizes; `QueryCollection` (`collections.go:263`) runs the filter twice (count + page) with `OFFSET` paging (`:241,311`; also `feeds.go:364`); the capacity sampler and operator stats run `SUM(octet_length(payload))` over the whole table (`operator.go:46,105`, `stats.go:62`) every five minutes. Fix: `octet_length` in SQL for sizes, keyset paging, a maintained byte counter or `pg_total_relation_size` for capacity. Audit B M1, M2, M4. |
| P8 | open | **Mailbox cache is unbounded and stale.** `internal/mda/delivery.go:106,154,184,294` `mailboxCache map[string]mailboxes.Mailbox` grows without bound and keeps old settings after an MMA update. B6 made retention maintenance storage-wide so that half is closed. Fix: bounded LRU (or drop the cache and rely on the DB), invalidate on `updateConfig`. Audit B M5. |

## Architecture

| ID | Status | Item |
|----|--------|------|
| A1 | open | **Authorization is re-implemented in eleven places with four response shapes.** Each handler checks owner/ACL itself and answers differently. Fix: one `authorize(sc, resource, action)` in `internal/protocol/wire` (or a middleware) returning `mailboxes.UnauthorizedError`, so `wire.Classify` gives one shape. Audit C M3, M4. |
| A2 | open | **No unit tests for the handlers, mailbox types, registry or storage interface.** `internal/protocol/*/handler_test.go` does not exist; authorization is covered only by integration tests that skip without a DSN. CI now runs the DB suite (B8) so they execute, but a handler test with `forgetest.NewPipeStream` and the storage mock in `internal/mta/router_test.go` would be fast and precise. Do this alongside A1. Audit C M8. |
| A3 | open | **Client edge cases.** `DeleteDocument` (`pkg/client/client.go:1311`), `DeleteCollection` (`collections.go:195`) and `DeleteCollectionItem` (`:330`) return `(true, nil)` on any status but 404, so a 403 or 500 reads as deleted; `PatchDocument` (`client.go:1239`) returns a result on failure without a typed error; there is no `Close()`; server selection (`client.go:129-133`) never fails over past the first preferred server. Fix: map non-2xx to `ProtocolError` like the feed/admin ops do (B1), add `Close`, try the next server on dial failure. Audit C M9. |
| A4 | open | **Process lifecycle.** `cmd/ricochet/main.go:172-178` waits for one signal and a second is ignored while `Stop` hangs; `internal/server/server.go:72,86,147,161,166,241` `isRunning` is a plain bool read from several goroutines; a failure in `initializeP2P` (`:117`) after `initializeStorage` (`:100`) leaks the pool. Fix: second signal exits hard, `atomic.Bool`, `Start` unwinds what it built. Audit C M10. |
| A5 | open | **Dead schema and tags.** `schema.sql:94-115` `block_store` and `:307,322` the two views are referenced by no Go code; `ServerConfig` carries `yaml:` tags (`internal/core/config.go:21-22` etc.) but is never decoded from YAML (only `yamlFileConfig` at `:749` is). Fix: drop the table and views in the upgrade section (or document why they stay), remove the tags. Audit C L3, M7. |
