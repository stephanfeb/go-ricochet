# Backlog

The open findings from the [2026-09-13 release audit](audit-2026-09-13/README.md)
that sat below its blocker line, plus anything found since. The eleven
blockers are done (see the status note at the top of the audit). This file
is the working list: one item at a time, one commit per item, the full
suite on a fresh database after each, the row updated in the same commit.

**How to use this file.** Pick the next `open` item, verify its anchors
(line numbers drift), fix it, add the test that would have caught it, mark
the row `done <date>` naming the test, in the same commit as the fix
(`git log -S<test name>` finds it). When an item is deliberately not going
to be fixed, mark it `wontfix` with one line of reasoning so it is not
re-investigated. Anchors are `file:line` as of the commit that last edited
this file.

Suggested order: the four correctness bugs a user can hit today (P5, P4,
P3, S1), then the one security item with no workaround (S2), then the rest
by section.

## Security

| ID | Status | Item |
|----|--------|------|
| S1 | done 2026-09-13 | **Patch If-Match was checked outside the transaction.** `internal/storage/postgres/postgres.go:685` `PatchDocument` reads with `GetDocument`, compares `ContentHash` to `ifMatch`, then calls `PutDocument(..., ifMatch=nil)`, so two concurrent patches both pass the check and the second overwrites the first. Fixed: `PatchDocument` now begins its own transaction, reads the row with `SELECT ... FOR UPDATE`, checks If-Match, merges, and writes through `putDocumentLocked` (the body of `PutDocument`, now shared) before committing. This also closes the lost update between two patches without If-Match. Tests: `TestConcurrentPatchesWithSameIfMatchAdmitOne`, `TestConcurrentPatchesWithoutIfMatchAllApply` (`internal/storage/postgres`; the second fails reliably on the old code, the first only when the race lands). Audit A M-1, B H6. |
| S2 | done 2026-09-13 | **Registry and presence trusted the JSON `server_id`, not the GossipSub signer.** `internal/registry/registry.go:218-236` uses `msg.ReceivedFrom` only to skip its own messages, then stores the announcement under `info.ServerID` from the payload. Presence events (`internal/presence/events.go:34,59,73`) are decoded the same way. Any peer on the topic can overwrite another server's entry or publish presence for peers it does not have. Fixed: `Registry.handleAnnouncement(from, data)` keys by `msg.GetFrom()` (the StrictSign-verified publisher) and refuses a payload naming another server; `Tracker.handleMessage(from, serverID, data)` refuses a message on a server's topic unless the signer is that server and the payload names it. Tests: `TestAnnouncementMustBeSignedByItsServer`, `TestForgedAnnouncementOverGossipSubIsIgnored` (three forge nodes over real GossipSub; fails on the old code), `TestTrackerIgnoresPresenceFromAnotherPublisher`. The Dart client's own registry/presence consumers (`../ricochet-dart-client`) still trust the payload: noted as N4. Audit A M-3. |
| S3 | done 2026-09-13 | **Raw Postgres error text reached clients.** `internal/protocol/mma/handler.go:234,266,292,327,390,443` and `internal/protocol/msa/handler.go:182,280` put `err.Error()` in the response; SCA does the same. A constraint name or SQL fragment is an information leak and a wire contract nobody meant to make. Fixed: `wire.ClientMessage(err)` returns the wording of a recognised client-facing error (mailbox full, quota, forwarding refused, validation, not-found sentinels, conflicts, JSON decode, rate limit, overload) and a fixed phrase per status for anything else; `wire.LogRejection(sc, status, err)` logs the real error with peer, protocol and stream id (there is no request id). Applied in every protocol's pipeline error writer, both MSA submit paths, SCA query, and the thirteen MMA "failed to …: %v" responses via `failed()`. Also classifies `mta.RateLimitError` as 429 and `mta.ValidationError` as 400 (both were 500). Tests: `TestClientMessageHidesDatabaseErrors`, `TestClientMessageKeepsClientFacingErrors` (`internal/protocol/wire`), `TestStorageErrorsAreNotEchoedToClients` (integration; closes the pool under a live server, fails on the old code). Audit A M-6. |
| S4 | done 2026-09-13 | **Directory search was an unbounded, unescaped `ILIKE`.** `internal/storage/postgres/postgres.go:919` builds `coalesce(display_name,'') ILIKE $n OR coalesce(bio,'') ILIKE $n` with `%q%`; `%` and `_` in the query are wildcards, there is no length cap, and the FTS index is unused. Fixed: the query is capped at `storage.MaxDirectoryQueryLength` (100 bytes, `ErrDirectoryQueryTooLong` → 400), reduced to its letters and digits, and rendered as a prefix tsquery (`'ali':* & 'cryp':*`) against the `idx_directory_fts` expression, so the search is index-backed (Bitmap Index Scan verified) and carries no pattern or tsquery syntax; a query with no words returns an empty page without touching the database. No `ILIKE` remains. The storage Info log of the full SQL and args, and the handler's Info log of the query text, are now Debug and carry only booleans. Test: `TestBrowseDirectoryTreatsWildcardsLiterally` (`internal/storage/postgres`; fails on the old code). Audit A M-6, B M3. |
| S5 | done 2026-09-13 | **Every per-peer limit is keyed by a free identity.** Rate limits, admission per-peer caps, mailbox quotas and forwarding trust are all per peer ID, which costs nothing to mint. Decided: per-peer limits are fairness controls; the abuse controls are `max_concurrent_connections` and admission control, which no identity rotation escapes. Found on the way: go-libp2p's resource manager was silently applying its own per-address policy to every host, 8 concurrent connections and 0.2 new connections/s per IPv4 address (IPv6 /56), which turns away clients sharing a carrier-NAT or office address. go-p2p-forge v0.1.2 now builds the resource manager explicitly in all cases, drops the per-address rate limit, and exposes `max_connections_per_ip` (`host.Config.MaxConnectionsPerIP`), wired from ricochet's `performance.max_connections_per_ip`, default 0 = no cap. README Security has a new "Identity Is Free" subsection saying all of this. Tests: `TestResourceManagerPerAddressPolicy` (forge `host`), `TestPerIPConnectionCapConfig` (`internal/core`). Audit A M-7. |
| S6 | done 2026-09-13 | **Unbounded client strings were persisted as index keys.** Folder path was bounded in B6 (`core.MaxFolderPathLength`). Still unbounded: document content type (`internal/protocol/sda/handler.go`), collection key and name (`sca`), feed title/description (`sfa`), directory display name and bio (`sda` directory ops). `validatePath` exists in each handler (`sfa:677`, `sda:1072`, `sca:715`) and is the place to add sibling validators. Fixed: bounds are public constants in `pkg/wire/limits.go` (content type, collection name and key, display name, avatar hash 256 B; feed title 256 B; description and bio 4 KiB; extras 4 KiB as JSON; entry type 64 B); `wire.CheckString`/`CheckJSONSize` (`internal/protocol/wire/fields.go`) return a `FieldError` classified 400 with the field named. Applied in SDA put and batch put (content type), directory join and the directory-listing document materialisation (which now logs and skips an over-bound listing), the SCA validation middleware (key, name) and the SFA validation middleware (title, description, entryType). Tests: `TestCheckString`, `TestCheckJSONSize` (`internal/protocol/wire`), `TestClientStringsAreBounded` (integration, one refusal per field plus values at the bound; fails on the old handlers). Audit A M-8. |
| S7 | done 2026-09-13 | **World-readable stores were undocumented.** Documents, feeds, collections and the directory are readable by any peer by design; README never said so. Done: README Security opens with "What Any Peer Can Read", a per-store table of who reads and who writes (verified against the owner checks in `sda`/`sfa`/`sca` handlers: reads open, writes owner-only, collaborative feeds take `APPEND` from anyone), plus the fact that the server never encrypts store contents; the feature list links to it; `doc/MAILBOX_LIFECYCLE_AND_ACLS.md` gained Gotcha 6 saying ACLs are a mailbox thing. No code; no test. Audit A I-1. |
| S8 | open | **Encryption has no forward secrecy and is not bound to the envelope.** `pkg/client/encryption.go` NaCl box with static X25519 keys derived from the identity; ciphertext is not bound to sender/recipient/folder, so a captured ciphertext can be replayed into another folder. Design-level. Minimum: include recipient, folder path and message id as associated data or in the plaintext header and verify on decrypt; document that forward secrecy is out of scope. Audit A L-3. |

## Performance

| ID | Status | Item |
|----|--------|------|
| P1 | open | **Submission is five round-trips plus a count plus a trigger.** `internal/storage/postgres/postgres.go:236` `StoreMessage`: tx begin, sequence `UPDATE ... RETURNING`, insert, then `trg_message_access` (`schema.sql:287-297`) updates the mailbox row again inside the same tx; the MDA adds a `COUNT(*)` for the cap and, for public mailboxes, two DELETEs with a sort per message. Fix: fold the count into the sequence update (`UPDATE mailboxes SET seq = seq+1, message_count = ...`), drop the trigger in favour of the same statement, move public-mailbox pruning to maintenance. Measure with `ricochet-bench` before and after (`doc/BASELINES.md`). Audit B H1. |
| P2 | open | **Three or four Info log lines per request on the hot path.** Counts today: msa 2, maa 4, mma 5, sda 3 (`grep -c Logger.Info internal/protocol/*/handler.go`). Fix: one Info line per request at the response writer (status, op, duration, peer), everything else Debug. Audit B H2. |
| P3 | done 2026-09-13 | **Notifier was built before the presence monitor, and never left a topic.** `internal/server/server.go:442` constructs `mda.NewNotifier(..., s.presenceMonitor, ...)` while `s.presenceMonitor` is assigned at `:455`, so the notifier's presence check (`internal/mda/notifier.go:110`) is always nil and it dials every recipient, online or not. `notifier.go:154` joins a GossipSub topic per shared/public mailbox and nothing leaves. B7 bounded the goroutines (`WithWorkers`). Fixed: the monitor is built first and passed as an `mda.PresenceChecker` (guarded so a nil monitor never becomes a non-nil interface; startup logs `presence_checked`); the notifier tracks joined topics, leaves one on `DeleteMailbox` and leaves any idle for 15 min on a sweep started with the server. Needed `Node.LeaveTopic` in go-p2p-forge v0.1.1. Tests: `TestNotifierSkipsOfflineRecipient`, `TestNotifierLeavesTopicOnMailboxDelete`, `TestNotifierLeavesIdleTopics` (`internal/mda`); `TestLeaveTopicUndoesJoin` (forge `node`). Audit B H3, C M2. |
| P4 | done 2026-09-13 | **Presence marked every still-connected peer offline after 120 s.** `internal/presence/service.go:103` writes `connectedPeers[pid] = time.Now()` at connect only; the sweep at `:331-336` evicts anything older than `TimeoutDuration`. A peer connected for two minutes is announced offline while its connection is up. Heartbeat (`:291-294`) serialises every online peer ID into one message and hits the 1 MiB pubsub cap around 18k peers. Fixed: the sweep now reconciles the online set against `host.Network().Peers()` on `presence_check_interval` (a peer is online for as long as it is connected; `presence_timeout_sec` is only the TTL advertised on events), and the heartbeat is paged at 4096 IDs with the tracker reassembling a sequence before applying it. Tests: `TestLongConnectedPeerStaysOnline`, `TestReconcileRepairsMissedNotifications`, `TestHeartbeatPagesBoundMessageSize`, `TestTrackerReassemblesPagedHeartbeat` (`internal/presence`). The Dart client library (`../ricochet-dart-client`, `lib/client/presence_tracker.dart`) consumes these heartbeats and gained the same page reassembly (`HeartbeatAssembler`) the same day; ship both sides together. Audit B H4. |
| P5 | done 2026-09-13 | **`GetOrCreateMailbox` was check-then-insert.** Now one `INSERT ... ON CONFLICT ON CONSTRAINT uq_mailbox_owner_folder DO UPDATE SET last_access_at = mailboxes.last_access_at RETURNING ..., (xmax = 0) AS created` in `internal/storage/postgres/postgres.go`; concurrent first deliveries all get the same row, and a later call cannot change an existing mailbox's settings. Tests `TestConcurrentFirstDeliveriesShareOneMailbox`, `TestGetOrCreateKeepsExistingSettings` (`mailbox_race_test.go`); the race test fails on the old code with duplicate-key errors. Audit B H6. |
| P6 | open | **Shutdown drains nothing.** Handlers are registered with `host.SetStreamHandler` after `forge.Start` (`internal/server/server.go:489-499`), which forge's `Stop` does not track (`../go-p2p-forge/forge.go:32,134`), and `Server.Stop` (`server.go:161-182`) cancels the context and closes storage under in-flight queries. Fix: on stop, remove stream handlers, wait for in-flight requests (the admission controller knows the count) up to `ops.drain_delay`/`shutdown_timeout`, then close storage. Test: a request in flight during `Stop` completes or gets a clean 503, never a pool-closed error. Audit B M8, C M1. |
| P7 | open | **Heavy reads.** `GetDocumentHistory` (`postgres.go:777`) and HEAD load full bodies to report sizes; `QueryCollection` (`collections.go:263`) runs the filter twice (count + page) with `OFFSET` paging (`:241,311`; also `feeds.go:364`); the capacity sampler and operator stats run `SUM(octet_length(payload))` over the whole table (`operator.go:46,105`, `stats.go:62`) every five minutes. Fix: `octet_length` in SQL for sizes, keyset paging, a maintained byte counter or `pg_total_relation_size` for capacity. Audit B M1, M2, M4. |
| P8 | open | **Mailbox cache is unbounded and stale.** `internal/mda/delivery.go:106,154,184,294` `mailboxCache map[string]mailboxes.Mailbox` grows without bound and keeps old settings after an MMA update. B6 made retention maintenance storage-wide so that half is closed. Fix: bounded LRU (or drop the cache and rely on the DB), invalidate on `updateConfig`. Audit B M5. |

## Architecture

| ID | Status | Item |
|----|--------|------|
| A1 | open | **Authorization is re-implemented in eleven places with four response shapes.** Each handler checks owner/ACL itself and answers differently. Fix: one `authorize(sc, resource, action)` in `internal/protocol/wire` (or a middleware) returning `mailboxes.UnauthorizedError`, so `wire.Classify` gives one shape. Audit C M3, M4. |
| A2 | open | **No unit tests for the handlers, mailbox types, registry or storage interface.** `internal/protocol/*/handler_test.go` does not exist; authorization is covered only by integration tests that skip without a DSN. CI now runs the DB suite (B8) so they execute, but a handler test with `forgetest.NewPipeStream` and the storage mock in `internal/mta/router_test.go` would be fast and precise. Do this alongside A1. Audit C M8. |
| A3 | open | **Client edge cases.** `DeleteDocument` (`pkg/client/client.go:1311`), `DeleteCollection` (`collections.go:195`) and `DeleteCollectionItem` (`:330`) return `(true, nil)` on any status but 404, so a 403 or 500 reads as deleted; `PatchDocument` (`client.go:1239`) returns a result on failure without a typed error; there is no `Close()`; server selection (`client.go:129-133`) never fails over past the first preferred server. Fix: map non-2xx to `ProtocolError` like the feed/admin ops do (B1), add `Close`, try the next server on dial failure. Audit C M9. |
| A4 | open | **Process lifecycle.** `cmd/ricochet/main.go:172-178` waits for one signal and a second is ignored while `Stop` hangs; `internal/server/server.go:72,86,147,161,166,241` `isRunning` is a plain bool read from several goroutines; a failure in `initializeP2P` (`:117`) after `initializeStorage` (`:100`) leaks the pool. Fix: second signal exits hard, `atomic.Bool`, `Start` unwinds what it built. Audit C M10. |
| A5 | open | **Dead schema and tags.** `schema.sql:94-115` `block_store` and `:307,322` the two views are referenced by no Go code; `ServerConfig` carries `yaml:` tags (`internal/core/config.go:21-22` etc.) but is never decoded from YAML (only `yamlFileConfig` at `:749` is). Fix: drop the table and views in the upgrade section (or document why they stay), remove the tags. Audit C L3, M7. |
